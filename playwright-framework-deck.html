Design Pattern

Page Object Model (POM)

Each page on the site maps to a TypeScript class that encapsulates locators and user actions. Tests call page methods rather than interacting with raw selectors.

Pattern

  • Constructor takes a Playwright Page and declares all locators as readonly
  • Methods expose user-level actions: login, addProductToCart, clearCart
  • No assertions inside page objects — tests own verification
  • Locator strategies: getByRole, getByPlaceholder, data-qa attributes, CSS selectors

Playwright Feature

Custom Test Fixtures

Extending Playwright's base test object to inject page objects, ad blocking, accessibility tools, and automatic login state.

Page Object Injection

Each page object is created as a fixture, so tests declare dependencies instead of manual setup:

homePage: async ({ page }, use) => { const hp = new HomePage(page); await hp.navigate(); await use(hp); }

Auto Ad Blocking

Runs automatically (auto: true) for every test. Intercepts ad network requests at the BrowserContext level:

blockAds: [ async ({ context }, use) => { await blockGoogleAds(context); await use(); }, { auto: true }, ]

Logged-In User State

Auto fixture that signs in, clears the cart, and navigates home. Tests that need anonymous access override it:

// Override in spec to disable: test.use({ loggedInUser: async ({}, use) => { await use(); // no-op }, });

Accessibility Builder

Provides a factory function for axe-core scans pre-configured with WCAG 2.x tags:

makeAxeBuilder: async ({ page }, use) => { const make = () => new AxeBuilder({ page }) .withTags(["wcag2a", "wcag2aa", "wcag21a", "wcag21aa"]); await use(make); }
Data Management

Test Data Layer

Typed interfaces and exported constants keep test data separate from test logic. Random generators prevent duplicate-account collisions.

Typed Interfaces

Each data file defines a TypeScript interface, giving compile-time safety and autocomplete.

export interface LoginData { email: string; password: string; status: string; } export const validLoginData: LoginData = { email: 'random@boredom.com', password: 'admin', status: 'valid', };

Random Data Generators

Used by signup and contact tests to generate unique names and emails per run.

export function generateRandomName(): string { return `TestUser${Date.now()}`; } export function generateRandomEmail(): string { return `testuser${Date.now()}@example.com`; }
Why Date.now()? Each test run gets a unique timestamp-based identifier, avoiding signup collisions without needing an external library.

Shared Code

Utilities

Three focused utility modules handle cross-cutting concerns: ad blocking, dialog handling, and random data generation.

blockAds.ts

Route-level interception at the BrowserContext level. Blocks requests to Google ad networks (doubleclick, googlesyndication, googleadservices) so ads don't interfere with test stability.

await context.route( /doubleclick|googlesyndication|googleadservices/, route => route.abort() );

eventListener.ts

Handles browser dialog events. The page.once('dialog', ...) pattern accepts alert/confirm dialogs that would otherwise block test execution.

page.once('dialog', async (dialog) => { await dialog.accept(); });

randomData.ts

Timestamp-based generators for unique test user names and email addresses. Used by signup and contact test data to prevent collisions across test runs.

`TestUser${Date.now()}` `testuser${Date.now()}@example.com`

Quality

Best Practices Applied

Patterns and techniques in this framework that align with Playwright and test automation best practices.

Applied: Page Object Model
All page interactions are encapsulated in classes. Tests read like user stories rather than selector chains. Locators are declared once and reused.
Applied: Custom Fixtures
Extended Playwright's fixture system to inject page objects, manage browser state, and set up preconditions. Auto-fixtures handle ad blocking and login without repetitive setup code.
Applied: Separated Test Data
TypeScript interfaces enforce data shape at compile time. Test data lives in its own directory, independent of test logic. Random generators avoid flaky collisions.
Applied: Network Interception
Ad blocking via context.route() prevents flaky tests caused by third-party ad scripts loading unpredictably.
Applied: Multi-Browser Coverage
Configured for Chromium and WebKit, with Firefox ready to enable. Uses Playwright's device descriptors for realistic browser settings.
Applied: Accessibility Testing
Integrated axe-core via @axe-core/playwright for automated WCAG compliance checks. Configured with WCAG 2.0 and 2.1 Level A and AA tags.
Applied: Visual Regression Testing
Screenshot comparison with toHaveScreenshot() catches unintended UI changes. Dynamic areas masked to reduce false failures.
Applied: Dialog Handling
Browser dialogs (alert/confirm) handled via page.once('dialog') with assertion on dialog content before accepting.
Growth

Areas for Improvement

Opportunities to strengthen the framework further, based on Playwright best practices and real-world automation patterns.

Opportunity: Prefer User-Facing Locators
Some page objects use CSS selectors (.cart_delete, #submit_search) where getByRole() or getByTestId() would be more resilient to DOM changes.
Opportunity: Environment-Based Configuration
The base URL and credentials are hardcoded. Using .env files with dotenv (already scaffolded in the config) would allow easy switching between environments.
Opportunity: CI/CD Integration
The GitHub Actions workflow file is referenced in the README but not yet implemented. Adding CI would catch regressions automatically on every push.
Opportunity: Include All Tests in Default Run
Cart, accessibility, and visual specs are excluded from testMatch. Expanding to **/*.spec.ts ensures full coverage by default.
Opportunity: Retry and CI-Specific Config
Retries and forbidOnly are commented out. Enabling them for CI prevents accidental .only commits and handles intermittent failures gracefully.
Opportunity: Authentication State Reuse
The loggedInUser fixture logs in via the UI for every test. Playwright's storageState can save cookies/session and reuse them, cutting test execution time.
Takeaways

Key Learnings

Practical insights gained from building this framework from scratch.

Fixtures Replace Boilerplate

Custom fixtures eliminate repetitive beforeEach setup. Declaring homePage in the test signature means Playwright handles creation, navigation, and teardown automatically.

Auto-Fixtures for Cross-Cutting Concerns

Setting { auto: true } on ad blocking runs it for every test without any explicit call. The same pattern works for login state — and test.use() overrides it cleanly per-file.

Route Interception for Stability

Third-party ads caused random failures and slow loads. Blocking them at the network level via context.route() made the test suite significantly more reliable.

TypeScript Catches Data Mistakes Early

Defining interfaces like LoginData and paymentData means the compiler catches missing or mistyped fields before any test runs.

Dynamic Content Needs Masking

Visual regression tests fail on carousels and rotating content. The mask option in toHaveScreenshot() lets you exclude those areas while still catching layout regressions elsewhere.

Cart Cleanup Requires Careful Synchronization

Deleting cart rows in a loop needs explicit waits for DOM detachment (waitFor({ state: 'detached' })). Without it, stale element references cause flaky failures.

Dialog Handlers Must Register Before the Trigger

The page.once('dialog') listener must be set up before clicking the button that triggers the dialog. Registering it after means the dialog fires before the handler is ready.

Accessibility Testing Is Almost Free

Adding @axe-core/playwright and a fixture factory is minimal effort. Running WCAG scans as part of the suite catches accessibility issues that manual testing would miss.
